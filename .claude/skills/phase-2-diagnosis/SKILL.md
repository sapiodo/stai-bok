# Phase 2: Диагностика

**Цель фазы:** глубокий системный анализ проблемы. От типа корневой причины — к системной модели, от модели — к архетипу и типичной точке рычага.

**Концепты для опоры:** `concepts/04-iceberg-model.md`, `concepts/05-causal-loop-diagrams.md`, `concepts/06-system-archetypes.md`, `concepts/07-stocks-and-flows.md`.

---

## Маршрутизация — выбор инструмента

```
Тип корневой причины (из Фазы 1)
│
├── Простая / линейная
│   └── Метод А: 5 Why углублённый
│       Достаточно найти и устранить
│
├── Убеждения / ментальные модели
│   └── Метод Б: Iceberg Model
│       Вскрыть скрытые слои системы
│
├── Системная динамика
│   └── Метод В: CLD
│       Найти петли обратной связи
│
└── Смешанный / неясно
    └── Iceberg → CLD (структуры Iceberg = переменные CLD)
```

> **Канон pipeline:** Iceberg → CLD → Leverage Point. Структуры из Iceberg становятся переменными CLD.

---

## Метод А: углублённый 5 Why

Для простых линейных причин.

1. Возьми нежелательное явление
2. Задавай «Почему?», на каждом уровне выбирай ветку **max impact**
3. Допускай ветвление, но **не более 2 факторов** между уровнями
4. Продолжай до **границы влияния** — точки, за которой ты не можешь воздействовать
5. Вернись и выбери **оптимальную точку воздействия**

**Правило:** не останавливайся на первой управляемой причине. Пройди всю зону влияния, затем выбери лучшее соотношение усилий/результата.

**Выход:** корневая причина + оптимальная точка воздействия + стейкхолдеры за границей влияния.

---

## Метод Б: Iceberg Model — 4 уровня

Для корневых причин типа «убеждения / ментальные модели». Строй вокруг **конкретной сформулированной проблемы**, не системы абстрактно.

| Уровень | Вопрос | Что записать |
|---|---|---|
| **1. События** | Что произошло? Что наблюдаем? | Факты, инциденты, фичи продукта |
| **2. Паттерны** | Что повторяется? Какие тренды? | Закономерности, привычки, циклы |
| **3. Структуры** | Какие компоненты / правила / роли порождают паттерны? | Алгоритмы, бизнес-модели, процессы |
| **4. Ментальные модели** | Во что верят участники? Какие допущения? | Убеждения, принципы, нормы |

**Мультистейкхолдерный принцип:**
- **Структуры** — общие для всех участников
- **Ментальные модели** — РАЗНЫЕ у разных стейкхолдеров

Строй отдельные «ментальные срезы» для каждого ключевого стейкхолдера.

**После согласования** текстовой матрицы — предложи собрать **одну SVG-таблицу** для слайдов/отчёта:
- Строки: События → Паттерны → Структуры → Ментальные модели
- Столбцы: `Уровень` | `Содержание` (для 1-3) | по столбцу на стейкхолдера (для 4)
- В строках 1-3 в столбцах стейкхолдеров — «—» или объединение с «Содержание»
- Шрифт 12-14px, ширина до ~900px

**Выход:**
- Элементы уровня «Структуры» → переменные для CLD (Метод В)
- Ментальные модели → потенциальные точки рычага уровня 5 (парадигмы)

---

## Метод В: CLD — Causal Loop Diagram

Для системной динамики. Также — второй шаг после Iceberg.

**5 шагов:**

1. **Переменные** — из уровня «Структуры» Iceberg (или из цепочки 5 Why). Должны быть **измеримы** (могут расти/уменьшаться). Оптимум: 4-8 переменных.
2. **Стрелки** — кто на кого влияет
3. **Знаки**:
   - `(+)` — однонаправленное: A растёт → B растёт
   - `(−)` — обратное: A растёт → B падает
4. **Петли** по правилу чётности минусов:
   - **Чётное** число `(−)` → **R (Reinforcing / усиливающая)** — экспоненциальный рост или падение
   - **Нечётное** число `(−)` → **B (Balancing / балансирующая)** — стремление к равновесию
5. **Задержки** `→||(+)` — на стрелках с отложенным эффектом

**Антипаттерн:** строить CLD без предварительного Iceberg. Тогда переменные берутся «из головы», не из системного анализа.

---

## Распознавание системного архетипа

После CLD — определи архетип:

| Архетип | Структура | Диагностический сигнал | Ловушка | Типичная точка рычага |
|---|---|---|---|---|
| **Limits to Growth** | R + B (с delay) | «Раньше это работало» | «Давить сильнее» | Работать с ограничением |
| **Shifting the Burden** | B1 + B2 + R | «Без этого мы не можем» | «Это же работает» | Усиливать фундаментальное решение |
| **Fixes that Fail** | B + R (с delay) | «Проблема вернулась, но хуже» | «Мы это решили» | Прогнозировать последствия 2-го порядка |
| **Eroding Goals** | B1 + B2 | «Раньше ставили более высокие цели» | «Обстоятельства изменились» | Держать цель фиксированной |
| **Success to Successful** | R1 + R2 (zero-sum) | «Одно направление всегда выигрывает» | «Метрики не врут» | Независимые критерии оценки |

**Дерево диагностики:**

```
Проблема связана с ростом?
├── Да → Рост замедлился?
│        ├── Да → Limits to Growth
│        └── Нет → Конкуренция за ресурсы?
│                  ├── Да → Success to the Successful
│                  └── Нет → анализируй глубже
└── Нет → Проблема повторяется?
          ├── Да → Зависим от одного решения?
          │       ├── Да → Shifting the Burden
          │       └── Нет → Вернулась через время, но хуже?
          │                 ├── Да → Fixes that Fail
          │                 └── Нет → анализируй глубже
          └── Нет → Цели/стандарты снизились?
                    ├── Да → Eroding Goals
                    └── Нет → возможно комбинация
```

> В реальных системах часто действуют **несколько архетипов одновременно**. Дерево — стартовая навигация.

**Cognitive check после распознавания архетипа:**
1. Согласен ли пользователь? Его опыт подтверждает?
2. Что подтверждает? Какие факты совпадают?
3. Что противоречит? Не другой ли это архетип?

## Д2 ⛔ Стоп-точка

Покажи пользователю:
- Системную модель: Iceberg (4 уровня × стейкхолдеры) и/или CLD (переменные, R/B-петли, delays)
- Для Iceberg — SVG-таблицу после согласования текстовой структуры
- Архетип + структуру петель
- Типичную точку рычага архетипа

Спроси:
- Узнаёшь свою систему?
- Что упущено?
- Не другой ли архетип?
- Готов к Фазе 3?

---

## Антипаттерны фазы

- ❌ Строить CLD без Iceberg при смешанной причине (переменные из головы)
- ❌ Один Iceberg на всех стейкхолдеров (теряются разные ментальные модели)
- ❌ Архетип без проверки через cognitive check (вешаешь шаблон)
- ❌ Переменные CLD неизмеримы («хорошая атмосфера», «уровень доверия» — конкретизируй)
