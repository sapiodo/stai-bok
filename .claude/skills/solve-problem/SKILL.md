# Skill: системное решение проблемы (orchestration)

Сопровождает пользователя через 4 фазы решения проблемы. На каждой фазе — диалоговая стоп-точка (Д1..Д4), внутри фазы — короткие итерации.

## Когда применять

По **явной просьбе** пользователя. Триггеры: «решить проблему», «системный анализ», «анализ проблемы», «pipeline проблем», «5 почему», «iceberg-анализ», «найти архетип», «точка рычага», «портфель решений», «провести диагностику», «давай разберём ситуацию системно».

**НЕ срабатывать** на:
- «расскажи про iceberg» / «что такое CLD» → это `study-concept`
- «обработай транскрипцию» / «создай конспект» → это другие задачи, вне BoK

## Pipeline

```
[Фаза 1: Формулирование] → Д1 ⛔ → [Фаза 2: Диагностика] → Д2 ⛔ →
[Фаза 3: Решение] → Д3 ⛔ → [Фаза 4: Реализация и сопровождение] → Д4 ⛔
```

Каноны фаз (читай перед выполнением соответствующей фазы):

1. `phase-1-formulation.md` — проблематизация, классификация, корневая причина
2. `phase-2-diagnosis.md` — Iceberg, CLD, системные архетипы
3. `phase-3-solution.md` — 5 уровней рычага, стейкхолдеры, портфель
4. `phase-4-implementation.md` — эксперименты, риски, сопровождение

## Входные данные

Минимум для старта:

- **Система / продукт / организация** — что анализируем
- **Нежелательные явления** — что беспокоит
- **Стейкхолдеры** — кто затронут (хотя бы предварительно)

Если данных не хватает — запроси одним коротким сообщением.

## Режим коротких итераций (по умолчанию)

Внутри каждой фазы:
- После каждого шага — покажи результат, спроси «Верно? Корректировки?»
- Если уточнение — интегрируй и покажи обновлённую версию
- Если «дальше» / «ок» — следующий шаг
- Допустимо объединить 2 связанных шага

## Диалоговые точки

На каждой Д-точке:

1. Покажи **полный результат фазы** — все таблицы, цепочки, диаграммы, портфели. Без «см. выше».
2. Спроси: согласен? нужны правки? готов к следующей фазе?
3. Дождись подтверждения, **не уходи в следующую фазу автоматически**.

Если пользователь говорит «вернёмся к фазе N» — перечитай канон этой фазы, не пропускай уже зафиксированное.

## Cross-link с concept-study

Когда на любой фазе пользователь хочет глубже разобрать конкретную модель (например, узнать про Iceberg или архетип Limits to Growth) — предложи:

> «Хочешь разобрать `<концепт>` отдельно по 5-слойной структуре? Прервёмся, запустим `/study-concept <slug>`, потом вернёмся к фазе N».

Соответствие фаз и концептов:

| Фаза | Концепты для углубления |
|---|---|
| 1 | `cynefin`, `problem-formulation`, `five-whys` |
| 2 | `iceberg-model`, `causal-loop-diagrams`, `system-archetypes`, `stocks-and-flows` |
| 3 | `leverage-points`, `stakeholder-map`, `effort-impact`, `hypothesis-portfolio` |
| 4 | `experiment-design`, `evaporating-cloud`, `creative-tension`, `scenario-thinking`, `strategic-bets` |

## Два трека решений

Если ситуация требует и коррекции, и системного улучшения — веди 2 трека:

| Трек | Горизонт | Фокус |
|---|---|---|
| **A: Коррекция сейчас** | Текущий цикл (недели) | Quick wins, работа с тем что есть |
| **B: Редизайн** | Следующий цикл (месяцы/год) | Структурные изменения, новые механики |

Для каждого трека — отдельный портфель гипотез на Фазе 3.

## Пояснительная записка сессии

При запуске pipeline предложи создать ПЗ:

- Имя: `<topic>-ПЗ-<YYYY-MM-DD>.md`
- Не в репо BoK (это в `.gitignore`). В рабочей папке студента.

**Структура ПЗ:**
- Контекст
- Ключевые решения (с датами и обоснованием)
- Ход работы (по фазам):
  - **Результат** — полный вывод фазы (без сокращений, ПЗ самодостаточна)
  - **Анализ ответов пользователя** — что сказал, почему важно, какой инсайт за корректировкой
- Открытые вопросы
- Артефакты (ссылки на CLD-диаграммы, таблицы, портфели)

## Принципы

- Следуй алгоритмам канонов точно.
- На каждой Д-точке — остановись и жди подтверждения.
- **Парадокс рычага:** сильнее рычаг → сложнее использовать.
- **Предупреждение Медоуз:** правильная точка, неправильное направление — частая ошибка.
- **«Нет субъекта — нет проблемы»** (Федин). Проблема субъективна, ситуация объективна.
- Не подменяй проблему решением. На Фазе 1 удержись от советов.
- При сомнении в выборе модели — спроси пользователя, не решай сам.

## Выходные артефакты
