# Phase 4: Реализация и сопровождение

**Цель фазы:** валидация гипотез через минимальные эксперименты, анализ рисков и конфликтов, плюс **сопровождение реализации**: каденция чекпойнтов, обратная связь, пересмотр гипотез. Опционально — стратегическое расширение.

**Концепты для опоры:** `concepts/12-experiment-design.md`, `concepts/13-evaporating-cloud.md`, `concepts/14-creative-tension.md`, `concepts/15-scenario-thinking.md`, `concepts/16-strategic-bets.md`.

---

## Принципы фазы

- **Эксперимент дешевле решения.** Сначала проверь, потом масштабируй.
- **Decision до старта** — заранее определи, что делаешь по каждому возможному результату (включая «серую зону»).
- **Сопровождение — это не отчётность.** Это loop: метрика → решение → пересмотр гипотезы. Если loop не запущен, эксперимент превращается в проект без обратной связи.
- **Anti-hallucination.** Различай факты и мнения, особенно когда часть анализа делал AI.

---

## Шаг 4.1. Дизайн экспериментов — Plan / Test / Metric / Decision

Для каждой гипотезы из портфеля:

| Поле | Вопрос | Пример |
|---|---|---|
| **Plan** | Что конкретно делаем? | A/B тест: с push vs без push |
| **Test** | Как проверяем? На ком? Как долго? | 500 пользователей, 2 недели |
| **Metric** | Что измеряем? Какой порог успеха? | Retention D14 ≥ 25% (vs 15% baseline) |
| **Decision** | Что делаем по результату? | ≥25% → масштабируем; <25% → следующая гипотеза |

**Правило минимального эксперимента:** что можно проверить за **1 неделю**? Не ищи идеальный тест — ищи самый быстрый способ узнать, стоит ли продолжать.

**Порядок проверки:**
1. Quick Wins — первыми (быстрый результат, мотивация)
2. Стратегические гипотезы — параллельно, запуск после Quick Wins

**Серая зона:** заранее определи, что считается неоднозначным (например, retention 18-19% при пороге 20%) и план B для этого случая.

## Шаг 4.2. Грозовая туча (TOC) — при конфликте

Если гипотеза содержит конфликт (например, «нужно больше push для DAU» vs «нужно меньше push для retention»):

```
         ┌──────────────┐
         │  Общая цель  │
         └──┬────────┬──┘
            │        │
    ┌───────▼──┐ ┌───▼───────┐
    │Потребность│ │Потребность│
    │    А     │ │    Б      │
    └───┬──────┘ └──────┬────┘
        │               │
   ┌────▼────┐    ┌─────▼───┐
   │Условие А│◄──►│Условие Б│  ← КОНФЛИКТ
   └─────────┘    └─────────┘
```

1. **Общая цель** — чего хотят все стейкхолдеры
2. **Две потребности** — кажутся противоречивыми
3. **Условия** — конкретные действия, создающие конфликт
4. Ключевой вопрос: **конфликт реален или это допущение?**
5. Найди **скрытое допущение** и проверь его

> Часто «неразрешимый» конфликт держится на скрытом убеждении. Грозовая туча помогает его обнаружить.

---

## Шаг 4.3. Риск-анализ

Для каждой ключевой гипотезы — 3 основных риска:

| Риск | Вероятность | Последствия | Митигация |
|---|---|---|---|
| Описание | Высокая / Средняя / Низкая | Высокие / Средние / Низкие | Что снижает риск |

**Правило стопа:** если у гипотезы все 3 риска = «высокая вероятность + высокие последствия» → пересмотри гипотезу или разбей на подгипотезы.

## Шаг 4.4. Сопровождение реализации (loop)

Эксперимент без сопровождения — это не эксперимент, а ставка без обратной связи. Установи каденцию:

| Элемент | Что фиксируем | Каденция |
|---|---|---|
| **Промежуточная метрика** | Текущее значение vs порог Decision | Еженедельно (для коротких экспериментов — ежедневно) |
| **Стоп-правило** | Условия аварийного прекращения (например, retention <10%) | Проверка при каждой сводке |
| **Обратная связь стейкхолдеров** | Что говорят пользователи / команда / инвесторы | Раз в 1-2 недели |
| **Пересмотр гипотезы** | Подтвердились ли допущения? Что узнали? | По итогу эксперимента + при «серой зоне» |
| **Решение** | Масштабируем / итерируем / останавливаем | Согласно Decision-правилу из шага 4.1 |

**Канон чекпойнта:**
1. Текущая метрика vs порог
2. Что нового узнали о системе (паттерны, не предусмотренные гипотезой)
3. Какое допущение из гипотезы оказалось ошибочным или подтвердилось
4. Решение на следующий период: продолжить / скорректировать / остановить

**Когда возвращаться к Фазе 3:** если 2-3 гипотезы подряд не подтвердились — возможно, неверно определён архетип или ментальная модель. Возврат к Фазе 2.

---

## Шаг 4.5. Anti-hallucination чеклист

Перед финализацией плана:

| # | Проверка | Вопрос |
|---|---|---|
| 1 | **Данные vs мнения** | Где факты, где предположения? |
| 2 | **Факты из AI** | Если использовал AI — проверил ключевые утверждения? |
| 3 | **Confirmation bias** | Не ищем ли только подтверждения? Что может опровергнуть гипотезу? |
| 4 | **Альтернативы** | Рассмотрели минимум 2 альтернативных объяснения / решения? |

## Стратегическое расширение (опционально)

> Применяй при стратегическом планировании, формировании видения продукта, подготовке к финальному Showcase. Не нужно для проверки одной гипотезы.

### Creative Tension (Senge)

Разрыв между ясным видением и текущей реальностью. Два способа снять напряжение:
- ✅ Подтянуть реальность к видению (действовать)
- ❌ Снизить видение до реальности (архетип **Eroding Goals**)

**Алгоритм:**
1. **Видение (3 года)** — каким должен быть продукт через 3 года (2-3 предложения)
2. **Реальность** — текущее состояние честно, без приукрашивания
3. **Разрыв** — в чём ключевое расхождение
4. **2-3 стратегические ставки** — действия, закрывающие разрыв

> Держи видение фиксированным. Если разрыв велик — меняй план, а не цель.

### Сценарное мышление — 2×2 матрица

1. Определи **2 ключевых неопределённости** (то, что не контролируешь и не знаешь, как развернётся)
2. Построй **матрицу 2×2** — 4 сценария
3. Каждому — название и нарратив (2-3 предложения)
4. Для каждого: что делать?
5. Типы стратегий:
   - **Robust** — работают во всех 4 сценариях
   - **Contingent** — работают только в 1-2

### Стратегические ставки — ОНМС

Ставка = действие в условиях неопределённости с высокими последствиями.

| Критерий | Вопрос |
|---|---|
| **Обоснованность** | На чём основана? Какие данные и модели? |
| **Необратимость** | Насколько легко откатить? (высокая → больше проверки до запуска) |
| **Масштаб** | Какой потенциальный эффект — на продукт / рынок / экосистему? |
| **Субъектность** | Кто реализует? Личный / командный / организационный уровень? |

## Д4 ⛔ Стоп-точка

Покажи:
- Планы экспериментов (Plan/Test/Metric/Decision) для всех гипотез
- (если есть конфликт) Грозовая туча + найденное скрытое допущение
- Матрицу рисков ключевых гипотез
- План сопровождения (каденция, стоп-правила, чекпойнт-канон)
- Anti-hallucination check
- (опц.) Стратегическое расширение

Спроси:
- Готов запускать?
- Каденция чекпойнтов согласована?
- Решение по «серой зоне» определено?
- Нужно ли стратегическое расширение?

## Антипаттерны фазы

- ❌ Эксперимент без Decision-правила (любой результат — повод спорить)
- ❌ Сопровождение = отчётность без loop (метрика собирается, гипотеза не пересматривается)
- ❌ «Серая зона» обнаруживается уже после теста (надо определять до запуска)
- ❌ AI-генерация плана без anti-hallucination check (фейк-кейсы и галлюцинированные метрики)
- ❌ Снижать видение под реальность (Eroding Goals)
