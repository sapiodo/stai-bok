## Вопрос 1. Уровни Iceberg — классификация

Вы анализируете Яндекс.Музыку. К какому уровню Iceberg относится утверждение «Алгоритм рекомендаций подбирает плейлист на основе истории прослушиваний»?

- a) События
- b) Паттерны
- c) **Структуры**
- d) Ментальные модели

**Пояснение:** Алгоритм рекомендаций — это механизм (технология, процесс), который порождает паттерны поведения. Это уровень «Структуры». Событие — «пользователь послушал плейлист». Паттерн — «пользователь каждый день слушает "Мой плейлист дня"». Ментальная модель — «алгоритм знает мой вкус лучше меня».

## Вопрос 2. Уровни Iceberg — ментальные модели

Вы анализируете сервис доставки еды. Какое из утверждений относится к уровню «Ментальные модели»?

- a) Курьер доставил заказ за 45 минут вместо обещанных 30
- b) Время доставки систематически превышает обещанное в вечерние часы
- c) Промокоды «-30% на первый заказ» привлекают пользователей, но не удерживают
- d) **«Люди готовы переплатить за удобство — скорость не так важна»**

**Пояснение:** (a) — событие (конкретный факт). (b) — паттерн (повторяющийся тренд). (c) — структура (механизм привлечения). (d) — ментальная модель: убеждение команды, которое формирует решения о продукте.

## Вопрос 3. Iceberg — направления анализа

В какой ситуации вы используете Iceberg Model «снизу вверх» (от ментальных моделей к событиям)?

- a) **Хотите понять, как убеждения команды порождают конкретные проблемы в продукте**
- b) Наблюдаете баг в продукте и ищете его причину
- c) Фиксируете тренд падения retention и анализируете, почему
- d) Считаете количество обращений в поддержку за квартал

**Пояснение:** «Снизу вверх» — генеративный режим: от убеждений к структурам, паттернам и событиям. Помогает понять, как именно ментальные модели порождают наблюдаемое поведение. «Сверху вниз» — диагностический: от событий к корневым убеждениям.

## Вопрос 4. CLD — определение знака стрелки

Связь: «Количество функций в приложении → Сложность интерфейса». Какой знак?

- a) **+ (same direction): больше функций → сложнее интерфейс**
- b) − (opposite direction): больше функций → проще интерфейс

**Пояснение:** Правило: «Если A растёт, B растёт?» Да — знак +. Больше функций → интерфейс становится сложнее. Это same direction.

## Вопрос 5. CLD — определение типа петли

Дана петля:

```
Количество пользователей --(+)--> Количество контента --(+)--> Ценность платформы --(+)--> Количество пользователей
```

Определите тип петли.

- a) **R (усиливающая) — 0 минусов (чётное)**
- b) B (балансирующая) — 0 минусов (нечётное)
- c) R (усиливающая) — 3 плюса (нечётное)
- d) Невозможно определить без дополнительных данных

**Пояснение:** Считаем число стрелок со знаком «−»: их 0. Ноль — чётное число → R (усиливающая). Это классический network effect: больше пользователей → больше контента → выше ценность → ещё больше пользователей. Вариант (c) — ловушка: считаем минусы, не плюсы.

## Вопрос 6. CLD — определение типа петли (2)

Дана петля:

```
Нагрузка на сервер --(+)--> Время ответа --(+)--> Уход пользователей --(−)--> Нагрузка на сервер
```

Определите тип петли.

- a) R (усиливающая)
- b) **B (балансирующая) — 1 минус (нечётное)**

**Пояснение:** Одна стрелка со знаком «−». Один — нечётное → B (балансирующая). Система стремится к равновесию: высокая нагрузка → медленный ответ → пользователи уходят → нагрузка падает. Это самокорректирующийся механизм.

## Вопрос 7. Delay — распознавание

Стартап запустил реферальную программу. В первый месяц — взрывной рост регистраций. Через 3 месяца обнаружили: большинство приглашённых пользователей неактивны, CAC вырос, а LTV реферальных пользователей вдвое ниже органических.

Где в этой ситуации проявляется delay?

- a) Между запуском программы и ростом регистраций
- b) **Между ростом регистраций и обнаружением низкого качества пользователей**
- c) Между решением о запуске и согласованием бюджета
- d) Delays в этой ситуации нет

**Пояснение:** Delay — между причиной (снижение качества пользователей из-за реферальной программы) и следствием (обнаружение проблемы через 3 месяца). В первый месяц метрики выглядели отлично — рост регистраций. Негативный эффект проявился с задержкой. Это делает связь между решением и последствием неочевидной.

## Вопрос 8. CLD — построение

Вы анализируете ситуацию: чем больше студент готовится к экзамену, тем выше его уверенность. Чем выше уверенность, тем меньше он готовится. Чем меньше готовится, тем ниже результат.

Какая из CLD правильно описывает ситуацию?

- a)
```
Подготовка --(+)--> Уверенность --(+)--> Подготовка   [R]
```

- b)
```
Подготовка --(+)--> Уверенность --(−)--> Подготовка   [B]
```

- c) **Вариант (b): Подготовка --(+)--> Уверенность --(−)--> Подготовка [B]**

- d)
```
Подготовка --(−)--> Уверенность --(+)--> Подготовка   [B]
```

**Пояснение:** Больше подготовки → больше уверенности (знак +). Больше уверенности → меньше подготовки (знак −). Один минус → B (балансирующая). Это петля самоуспокоения: студент готовится, чувствует уверенность, расслабляется. Вариант (a) — ошибка в знаке второй стрелки. Вариант (d) — ошибка в знаке первой стрелки.

## Вопрос 9. Iceberg + CLD — интеграция

Вы анализируете Instagram. Заполнили Iceberg:
- **События:** Пользователь проводит 2+ часа, листая ленту
- **Паттерны:** Ежедневное «залипание», особенно перед сном
- **Структуры:** Алгоритмическая лента, бесконечный скролл, уведомления
- **Ментальные модели:** «Я просто проверю, что нового» / «Вовлечённость = ценность» (команда)

Какой элемент из уровня «Структуры» лучше всего подходит для построения R-петли вовлечённости в CLD?

- a) Уведомления о новых лайках
- b) **Алгоритмическая лента (подбирает контент по интересам)**
- c) Функция Stories
- d) Тёмная тема интерфейса

**Пояснение:** Алгоритмическая лента создаёт R-петлю: больше просмотров → больше данных для алгоритма → точнее подбор → интереснее контент → ещё больше просмотров. Это ядро механизма удержания. Уведомления (a) — важны, но создают B-петлю возврата, а не R-петлю вовлечённости. Stories (c) — формат контента, не механизм усиления. Тёмная тема (d) — не связана с динамикой.

## Вопрос 10. Конкурирующие петли

В продукте действуют две петли:
- **R-петля:** Больше контента → больше пользователей → больше авторов → ещё больше контента
- **B-петля (с delay):** Больше контента → информационный шум → пользователи уходят → меньше пользователей

Почему R-петля доминирует в начале, а B-петля «включается» позже?

- a) R-петли всегда сильнее B-петель
- b) B-петля содержит ошибку в знаках
- c) **B-петля содержит delay: информационный шум накапливается постепенно, а R-петля работает сразу**
- d) В системе может быть только одна доминирующая петля

**Пояснение:** Delay в B-петле — ключевое объяснение. R-петля работает мгновенно: каждый новый автор сразу добавляет контент. B-петля запаздывает: шум накапливается постепенно, пользователи терпят до определённого порога. Из-за delay R-петля успевает набрать силу, прежде чем B-петля начнёт тормозить. (a) — неверно: B-петли могут доминировать. (d) — неверно: петли конкурируют.
